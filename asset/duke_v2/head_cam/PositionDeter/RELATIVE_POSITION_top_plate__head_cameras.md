# Relative pose spec: CNC_body03_x1_top_plate ↔ the two head-camera gimbals

> For whoever mounts the two head-cameras onto the robot body's top plate. All values are parsed/computed per-entity from the STEP files — **not estimates**.
> Data sources: `HeadCameraV2.step` (Fusion 360 export, AP214, millimeters) + `HeadCameraV2_dual.step` (180°-rotated twin, generated by `mirror_step.py`).
> Parsed: 2026-06-12. Tools: `extract_relative_positions.py`, `mirror_step.py` (hole-center computation).

---

## ⚠️ How this differs from the v19 doc (CNC_body ↔ gimbal_mount_v2)

The v19 doc used "transforms between component local origins." **That method does not work for this STEP**: the top plate, gimbal_mount, gimbal_neck, and gimbal_arm are all **modeled in place** in this export — their assembly placements are all identity transforms (origin (0,0,0), no rotation; see the provenance table at the end), so origin-to-origin distances are always 0 and carry no mounting information. The position information is embedded in the geometry coordinates. This doc therefore uses **physical features** (top-plate top face, central hole center, plate axes) as the mounting reference.

## TL;DR (mounting spec)

Mounting reference frame **P** (top-plate feature frame) is defined as:
- Origin = center of the top plate's **central large hole**, on the plate's **top face** (global coords (0, 0, 412))
- +Z = top-face normal (vertically up); +X / +Y = the plate's own length/width axes (parallel to the global axes)

| Item | Left gimbal (original) | Right gimbal (twin) |
|---|---|---|
| gimbal_mount bottom face | flush with the plate top face (P-frame z = 0) | same as left |
| **Yaw axis location** (P-frame) | vertical line through **(x=0, y=−65) mm** | vertical line through **(x=0, y=+65) mm** |
| Component rotation vs plate | **none** (component axes aligned with plate axes) | **rotated 180° about the hole-center vertical axis** |
| Pitch axis (P-frame) | along Y, through (x=0, z=+213.44) | same as left (the two axes are collinear) |
| D435 optical-center height | P-frame z ≈ +250 (global z=662) | same as left |

Both gimbals share the same top plate; the two yaw axes are **130 mm** apart, centered on the hole.

Machine-readable form (P-frame, meters; quaternion wxyz):

```json
[
  {"name": "head_camera_left",  "translation_m": [0.0, -0.065, 0.0],
   "quaternion_wxyz": [1, 0, 0, 0]},
  {"name": "head_camera_right", "translation_m": [0.0,  0.065, 0.0],
   "quaternion_wxyz": [0, 0, 0, 1]}
]
```

(right's quaternion (0,0,0,1) = 180° about Z; the translation is where the yaw axis meets the top face.)

### MJCF example (meters)

```xml
<body name="robot_top_plate">
  <!-- top-plate geometry; P-frame origin at the hole center, on the top face -->
  <body name="head_camera_left"  pos="0 -0.065 0" quat="1 0 0 0"> ... </body>
  <body name="head_camera_right" pos="0  0.065 0" quat="0 0 0 1"> ... </body>
</body>
```

Note: `view_dual_articulated.xml` does not split out this hierarchy — it models directly in the CNC global frame (plate top face z=0.412). The values above match it exactly, so the two can be cross-checked.

## Self-check

- In Fusion/MuJoCo, measure the horizontal spacing of the two yaw axes; it should be 130.00 mm (±0.01).
- Measure the gap between each gimbal_mount bottom face and the plate top face; it should be 0 (flush).
- In MuJoCo, load `view_dual_articulated.xml` and query the `jnt_pos` of the `yaw_left` / `yaw_right` joints: they should be (0, ∓0.065, ·), matching this doc.
